The gate — read before installing anything

Three decisions arrived from three directions and all of them land in front of the same DynDOLOD run. Get this wrong and the ninety-minute generation chain runs three times instead of once.

  1. Seasons needs terrain LOD generated per season via xLODGen, then TexGen and DynDOLOD run with Seasons enabled. It cannot be added retroactively.
  2. A Clear Map of Skyrim ships custom DynDOLOD rules that build map LOD as fake object LOD level 32. Install before generation and the map comes free in the same pass.
  3. Every gameplay mod in the roleplay phase adds a plugin, and plugins invalidate tree LOD.

The chain HAS run once, on 6 September, without Seasons. DynDOLOD Output is 2.7 GB, TexGen 1.1 GB, and DynDOLOD.esm, DynDOLOD.esp and Occlusion.esp are all active. That run was the learning pass on a much smaller list. The plan is deliberately to run it once more, at the end, and only once — which is why gated mods should go in NOW rather than being held back.

Tree LOD is already stale — that is the stranded flat billboard in Whiterun. It stays broken until this runs.

Build order

Every constraint in this plan resolves into one sequence. The rule underneath it is simple: anything that changes a plugin or a world static mesh must be in place before the generation chain runs, because both invalidate LOD. Things that touch neither are unconstrained and can happen at any point, in parallel, which is what the free lane is for.

XEverything else before the chain

X · the sweep so the generation never runs twice
X-0
A correction, and it makes the free lane much biggerrule fixed
"Any plugin gates behind the run" was too broad, and it had been repeated several times in this plan. Sheson's actual mechanism is that tree LOD unloads by matching form ids, and it breaks when the load order of plugins that add tree references changes. An armour mod's ESP adds no world references.

The real rule: world references and static meshes gate behind the chain. Item and actor mods do not.

So the free lane confirmed includes weapons, armour, clothing, jewellery, book covers and instruments; creatures, followers and any actor; audio, UI, animation behaviour, skin and overlays; and interior-only overhauls, because interiors have no LOD at all — the entire JK's series in this report is interiors. That matters directly for pillar 3: the wardrobe and adult content can grow forever without re-running anything.

Standing rules

Static mesh changes invalidate LOD too, not just plugin changes. City overhauls, 3D wall replacements, tree mods — all go in before the TexGen/DynDOLOD run, never after. Skin, face and overlay mods do not, because actors are not in LOD.
Skimpiest wins. Encoded in bodyslide_pick.ps1's $ModPriority. A milder replacer only ever wins an item nothing skimpier covers.
PGPatcher order is not negotiable. BodySlide → PGPatcher → TexGen → DynDOLOD. See P-6.
Check every Community Shaders change against neural rendering. nr_check.ps1 — it has caught a real regression once.
Steam files and the registry are off limits. No exceptions.
Verify every device write by reading the file back afterwards.
BodySlide Output stays at highest priority. Now automatic on install.
Check the body in the filename. BnP's primary MAIN file is the UNP build and it installed before anyone noticed. Towels arrived as the UBE variant the same way. Both looked like successful installs.
Verify the value, not the mechanism. Confirming a write landed says nothing about whether the value was right — that mistake overwrote three correct mod ids with wrong ones before it was caught.
Off-Nexus hosts need a live, reputable source for the link — a Nexus requirements section, a GitHub release. Never a search result, never recall, never a migration note older than a year. A fetch returning sensible-looking content is not verification: a clone and a compromised site read identically.
Endorsements measure history, not health. A stale base others are still actively patching is a defect. High Poly Head and ELFX both failed this and both looked fine by the numbers.
A check that cannot fail is not a check. On 8 September five separate checks reported success while measuring nothing: check_masters on a wrong-runtime DLL, check_masters again on a reversed load order that was master-legal, check_order before the sort had run, a guard test comparing $null to $null, and launch_check on a game that was crashing. Break it on purpose, confirm it fails, then fix it and confirm it passes.
Every external tool finds the Steam copy by itself. xEdit did it and actually cleaned three DLC masters in place. Standalone LOOT builds its game handle against it. Pandora wrote both its game and output paths there on first launch. Read the paths a new tool decided on BEFORE its first run — most write a config on first launch, which makes that check free.
Behaviour mods and DAR mods are not the same risk. A Nemesis_Engine folder means the mod rewrites the compiled behaviour graph the engine loads once at startup, and a bad one is a silent ucrtbase abort with no crash log. A DynamicAnimationReplacer folder means runtime condition swapping, where the worst case is an animation not playing. Check which before installing.
Update this plan after every batch. A stale plan is worse than none — it sent a session to "pick a UI" hours after the UI was installed.
Scripts, not clicking. Twenty tools in tools\ now — installs, FOMOD answers, conflict checks, BodySlide pruning, mod id repair, collection diffs.
